01 · Introduction

From assistants to autonomous actors

An AI agent is software that can perceive (read email, browse the web, query databases), reason through a multi-step plan toward a goal, act by running tools, writing code or sending messages, remember context across long-running tasks, and collaborate with people and other agents. The path there ran from single-turn chatbots in 2022, to human-in-the-loop copilots in 2023, to copilots executing tasks on their own in 2024, and now to orchestrated multi-agent teams in 2025 and 2026.

Under the hood a request flows from the user or orchestrator into LLM reasoning, then planning and memory, then tool execution against external systems: email and calendar, SaaS APIs, databases, code repos, the web and other agents. Two protocols glue it together. MCP (Model Context Protocol) connects agents to tools, and A2A (Agent-to-Agent) lets agents talk to each other.

Key shift: agents no longer suggest actions, they take them, with real credentials, on real systems, at machine speed.

03 · Attack surface

Every agent capability is also a vulnerability

Proofpoint's architecture view puts the agentic application in the middle. Above it sit enterprise information and tools (email, collaboration apps, web and SaaS, databases, documents, APIs). To one side are the ways it extends itself: MCP, agent skills (knowledge and scripts), A2A and vendor plugins. To the other are its users, both human and agentic, and underneath is the frontier model. Every one of those connections is an entry point.

Shadow AI · 73%

Share of workers using AI tools IT hasn't approved. Every enterprise has it and most security teams can't see it.

Agent autonomy · 8/20

Agents operating without human breaks, acting with real credentials beyond human-supervised workflows.

Novel vectors · 10

New risk categories in the OWASP Agentic Top 10: prompt injection, tool poisoning, memory corruption, cascading multi-agent failures.
Think of agents as first-week interns with admin credentials: moving fast, making decisions, with less oversight than any human employee.
04 · Risk taxonomy

OWASP Top 10 for Agentic Applications (2026)

The industry-standard list of agentic AI risks. The session singled out goal hijack, identity abuse, cascading failures and rogue agents as the highest-impact and most novel, with tool misuse, supply chain, memory poisoning and inter-agent comms close behind.

Highest impactAgent behavior & commsSupply chain & codeHuman factor
ASI01Agent Goal Hijack

Hidden instructions in email, web pages or documents redirect what the agent is trying to do. It targets the AI rather than the human. EchoLeak is the real-world case: hidden prompts turned copilots into silent data exfiltration engines.

ASI02Tool Misuse

The agent uses legitimate tools in unsafe ways. Nothing is technically unauthorized, which is what makes it hard to catch.

ASI03Identity & Privilege Abuse

Agents inherit broad permissions through long-lived tokens and service accounts, so an over-privileged agent has a catastrophic blast radius. Example given: one service account with access to all of M365, Salesforce and Jira.

ASI04Supply Chain Vulnerabilities

Compromised tools, plugins and MCP servers become the way in.

ASI05Unexpected Code Execution

Agents generate or run untrusted code as part of completing a task.

ASI06Memory & Context Poisoning

Corrupting RAG stores and persistent memory so later decisions start from bad context.

ASI07Insecure Inter-Agent Comms

Spoofed or intercepted agent-to-agent (A2A) traffic.

ASI08Cascading Failures

One prompt injection fans out across a multi-agent system and a compromised agent corrupts the others at machine speed. The session called it an entirely new vulnerability class with no analog in traditional security.

ASI09Human-Agent Trust Exploitation

Users over-trust agent outputs and actions and stop checking them.

ASI10Rogue Agents

Misaligned or compromised agents working against organizational goals: a super-powered insider threat with perfect patience and perfect speed, running 24/7 without oversight.

05 · Threat modeling

MAESTRO and the three planes of risk

MAESTRO (Multi-Agent Environment, Security, Threat, Risk & Outcome, from CSA in 2025) is a seven-layer threat model: foundation models, data operations, agent frameworks, deployment infrastructure, evaluation and observability, security and compliance, and the agent ecosystem on top. STRIDE and PASTA were built for static systems; MAESTRO handles dynamic multi-agent environments and cross-layer attack chains, such as a supply chain compromise cascading through an agent framework into data exfiltration. It has already been applied to the OpenAI Responses API and Google's A2A protocol. OWASP names the risks, MAESTRO gives you the method.

Content & model behavior

Prompts, outputs, training and retrieval data. Covered by the OWASP LLM Top 10.

Agents, tools & workflows

Autonomy, orchestration, tool execution, MCP and A2A. Covered by the OWASP Agentic Top 10.

Identities, privileges & data

Human and non-human identities, credentials, data flows. Covered by the OWASP NHI Top 10.

MAESTRO spans all three planes. The point: agentic security needs coverage across all of them at once, and no single framework is enough alone.

06 · Integrity

Agent integrity: the question frameworks don't answer

Agent integrity is the assurance that an agent stays within its intended purpose, authorized permissions and expected behavior on every interaction, tool call and data access. Framed as three dimensions: permissions (what it can do), intent (what it should do) and behavior (what it actually does). The job is checking that they line up, which means asking not whether it has permission but whether it should be doing this, for this task.

The double agent problem. A double agent is dangerous because everything on paper looks right, and AI agents create that condition by default. An agent infers what was probably meant and acts on its reasoning, so it can drift at any step: it might obey instructions buried in a document it was asked to summarize, decide the task needs systems outside its scope, or lose the thread and optimize for something else. None of this requires an attacker, so the baseline assumption has to be that alignment is temporary and contextual.

Semantic privilege escalation: the user asks for a document summary; the agent scans Google Drive for API keys and emails them to an outside address. Permissions: authorized. Behavior: active. Intended purpose: violated. Restricting access doesn't fix it (the access is the value) and neither does watching for unauthorized actions (these are authorized). You have to verify behavior against intent continuously and catch it in context.

Intent alignment

Does behavior match what the agent was asked to do?

Identity & attribution

Can every action be traced to a user, an agent and a purpose?

Behavioral consistency

Is it inside expected bounds for its purpose and configuration?

Full audit trails

Can you rebuild what happened step by step, with security context?

Operational transparency

Can you prove oversight to stakeholders and regulators?

Weakness in any one pillar compromises the whole. Today's stack leaves gaps here: CASB and SWG see traffic but can't read the meaning of an AI interaction, endpoint tools miss workflows that span systems and tool calls, IAM and RBAC check permission with no sense of task context, and AI firewalls judge a single prompt without seeing the wider workflow. None of them compares purpose, permissions and behavior.

Capabilities have to mature together; pushing one row ahead while others lag creates blind spots. The rollout path starts with visibility and discovery (inventory agents, LLMs and data connectors, map application graphs, because you can't secure what you can't see), then risk classification by data sensitivity, LLM type, deployment model, autonomy and user population. Next come per-agent acceptable-behavior policies written as manifests (allowed tools, data sources and LLMs, plus approval workflows), then detection through security-annotated logging and IBAC and anomaly detection in visibility mode wired into SIEM/SOAR, and finally inline enforcement and IBAC intent validation for high-risk workflows, widening by risk profile and regulation.

08 · Summary

Two layers, and what to do Monday morning

Layer 1 · Channel security

Email gateway prompt-injection and goal-hijack detection with sanitized views, web/SaaS/CASB and DLP extended to agent actions, identity threat defense for service principals and OAuth tokens, Nexus threat intel on malicious MCP servers, and awareness training on agent manipulation.

Layer 2 · AI runtime security

Shadow AI discovery across browsers, endpoints and dev environments, an AI firewall Intent Gate checking every tool call, the open-source Minibridge MCP proxy (TLS, auth, SBOM, OPA/Rego), context-aware DLP++, real-time threat protection and sandboxed runtimes.

Either layer alone leaves gaps; together they cover the full OWASP Agentic Top 10. The takeaways: agentic AI is already here and the gap grows every day it's ignored; use OWASP for the taxonomy and MAESTRO for threat modeling; think in both layers; start with shadow AI discovery, then add runtime protection, identity governance and cross-layer correlation; and move from checking permissions to continuously verifying behavior against intent.

An agent's alignment to its intended purpose is inferential, not architectural.
